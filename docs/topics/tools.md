# Tool layer

> Built-in tools + MCP dynamic tools, execution semantics, Shell, multimodal, perception cache. Must-read when changing `agent/tools/`, `agent/multimodal/`, `agentcore/mcp.rs`, `agent/runtime/react.rs`, `agent/runtime/shell.rs`.

## Overview

Tools are the agent's means of interacting with the environment: the LLM reads/writes memory, topics, knowledge base, sends messages/voice, runs shell, and analyzes attachments via tool calls. The tool contract is defined in `agentcore::tool` (platform-agnostic); implementations depend on `ToolContext` (chat_id/handler/db/shell/skill_manager/multimodal), and platform details are hidden behind the `Arc<dyn PlatformHandler>` trait — the tool layer has zero concrete platform imports.

## Design

### Tool abstraction (AgentTool)

`agentcore/tool.rs:AgentTool`: `name() / description() / schema() -> Option<Value> / execute(Value) -> Result<Value, ToolError>`. `schema` is the tool contract (JSON Schema); `execute` receives `Value` and runtime-deserializes it (hand-written impls only need to provide the schema to reuse the same call path).

- `ToolError{Msg(String), Execution(Box<dyn Error>)}`; `From<AppError>` / `From<serde_json::Error>` → Msg
- Result helpers: `tool_ok()` / `tool_data(data)` / `tool_err(msg)` / `MapToolErr::into_tool_err`
- Success results unified as `{ok: true, ...}` shape; errors unified as `ToolError::Msg/Execution`

### Macro: `#[hai_macros::tool]`

`crates/hai-macros/src/lib.rs:tool` generates `impl AgentTool`: name = struct name camel_to_snake; description = struct's **first-line doc comment**; schema = `schemars::schema_for!(Args)`; three forms: `args = none` / `args = Type` / no attribute (auto-assumes `{Struct}Args`).

### Hand-written impls

SendMessage / AnalyzeAttachment / RunShell — description depends on runtime state (`MessageCapability::Rich` distinction, `enabled_parsers` assembly, `sandbox_image` changes).

### Assembly (main-mode built-in tools + MCP append)

Key symbols: `agent/tools/mod.rs:get_main_agent_tools(ctx, enabled_parsers, sandbox_image)`, `get_wrap_up_tools(ctx)`.

```txt
skip → sleep → send (send_message always mounted; send_voice only when tts_enabled; generate_image only when image_gen_enabled)
→ topic → memory → knowledge → skills
→ multimodal (only when enabled_parsers is non-empty)
→ shell (always, description changes with sandbox_image)
+ MCP (engine.mcp_manager.list_all_tools())
```

Conditional mounting: skills internally judges `skill_manager.is_empty()` → empty Vec; send internally judges `tts_enabled` / `image_gen_enabled`; multimodal only when enabled_parsers is non-empty; shell always mounted.

Wrap-up subset: `get_wrap_up_tools` = topic/memory (**no skip** — wrap-up is a background task that must output a retained summary, it cannot "skip"; no MCP, no knowledge-base retrieval).

### Execution semantics (react loop)

Key symbols: `agent/runtime/react.rs:run_react_loop`, `execute_single_tool`.

- **Sequential execution**: `for call in &active_calls { execute_single_tool(...).await }`, each tool separately emits `ToolCall`/`ToolCallResult`. Reason: tools have side-effect ordering dependencies (topic link messages, memory writes), sequential execution guarantees a deterministic single turn and a traceable event stream.
- **Speaking contract** (`LoopMode::Main`): directly outputting text is not allowed. `stop = empty text && (has_skip || no calls)`; `retry = !stop && no send_message/send_voice && non-empty text && no non-skip calls` — has text but did not send a message → inject `DIRECT_OUTPUT_ERROR` + `ModelRetry{ResponseWithText}`, loop does not end; `ModelRetry` event is emitted after `TurnCompleted`.
- **Unknown tool name** → `ToolCallResult::err("Unknown tool: {name}")`
- **Tool results** flow into the message stream via `ToolResponse::from_tool_call`, presented as XML sections together with context; on error prefix `Error: {e}`
- LLM call retry: only network-class errors (reqwest timeout/connect, `is_retryable_ge`) retried at most 2 times, backoff `500ms × attempt`; api/auth errors passed through directly.
- Turn limit `react.rs:MAX_TURNS` (20) — prevents infinite loop from the model calling tools/retrying indefinitely.

### Shell execution

Key symbols: `agent/runtime/shell.rs:ShellRuntime`, `ContainerGuard`, `SandboxRuntime`.

- `ContainerGuard::create(runtime, image)` = `create --rm image sleep infinity` + `start`; **Drop → synchronous `rm -f`** (RAII double safety)
- `SandboxRuntime.ensure_container()`: lazily create and cache, reused across calls.
- `ShellRuntime::execute(command, workdir, skill_dir, timeout_secs)` (called while holding the `Arc<Mutex<ShellRuntime>>` lock): host runs `bash -c` (skill_dir as working directory); on sandbox container creation it **mounts the skill root dir read-only at the same path** (`-v <skills_root>:<skills_root>:ro`, source=target; `manager.rs:SkillManager::mount_dirs` returns the loaded dirs — at most 3 roots, not per-skill mounting; **the mount path must be absolute** — `SkillManager::load` absolutizes the skill root (`std::env::current_dir()` expands relative paths like `.agents/skills`, otherwise the container -v reports invalid container path)) — after the root is mounted, the `{baseDir}` (`<root>/<skill_name>`) subpath naturally exists in the container, `manager.rs:Skill::body` replacement unchanged; on exec skill_dir is used as the `-w` working directory (relative path also usable), no skill falls back to `/tmp` (container create command is only `sleep infinity`, doesn't create dirs — if the image lacks `/tmp`, `-w` fails). Don't use `docker cp` — when the target already exists without a trailing slash it nests copies (`/workspace/<skill name>/...`), and the `{baseDir}` absolute path never points to the copied content.
- Timeout `timeout_secs.unwrap_or(default_timeout)`, on timeout returns ToolError rather than silently truncating.
- `[sandbox] enabled=false` → no sandbox (host direct run), `run_shell`'s description changes accordingly.

### Multimodal (MultimodalService)

Key symbols: `agent/multimodal/mod.rs:MultimodalService`, `MediaSource{Url|Bytes|Base64}`, `SenseCfg`/`TtsCfg` (slots independently typed — image-gen/embedding have no param payload, hold `Endpoint` directly).

- Dual client: multimodal uses `agentcore::ApiClient` (OpenAI-compatible REST), not genai.
- Entry: `analyze_image` / `ocr` / `analyze_video` / `analyze_audio` / `speech` (TTS, PCM response auto-converted to WAV) + `EmbeddingService::generate_embedding` implementation.
- Image URLs passed directly to the provider (saves bandwidth), Sticker/Audio go as bytes; Video/Image non-Sticker go as URL.
- Unconfigured modality → `unavailable()` (`ErrorKind::BadRequest`); TTS unconfigured → send_voice not mounted.

**Prompt structure (fixed label templates, verified verbatim against mod.rs)**:

- Objective structure constants `IMAGE_STRUCTURE` / `VIDEO_STRUCTURE` / `AUDIO_STRUCTURE` are **sensory transcription templates** — the output reader is a **text model without multimodal support** (the main conversation model), and the analysis text serves as its "eyes/ears", hence completeness, fidelity, and high information density are required: opening role-setting (explicitly states "this description will be provided as the only visual/audio input to a text model that lacks image/audio understanding") → skeleton (Recognition → Basis → Scene overview → Layout / Timeline / Transcription → Details: → end Constraints:) — the recognition field = a single identification conclusion (derived from reasoning), nothing beyond this layer outputs subjective judgment.
- **Two independent analysis modes (mutually exclusive)**: basic analysis (no focus, `DEFAULT_IMAGE/VIDEO/AUDIO_PROMPT` = corresponding STRUCTURE) vs targeted analysis (focus passed, `*_JUDGMENT_PROMPT` positive expression, `build_prompt`'s Some(focus) branch — overrides the default analysis, does not attach the basic transcription structure).
- `DEFAULT_OCR_PROMPT` = pure extraction instruction (no structure layering, OCR untouched).
- Config `[auxiliary.vision] image-prompt` can override the built-in default (`multimodal/mod.rs:resolve_input`); when a tool/platform call passes focus, image-prompt is not involved.

**Perception cache chain**:

```txt
send_message attachment / analyze_attachment tool
  → TelegramMediaAnalyzer.download_attachment (platform/telegram/media.rs, message.find_attachment scans the most recent 200 messages)
  → analyze_part (Image+Sticker bytes / Image+Ocr+Video URL / Audio bytes)
  → MultimodalService analysis (no focus → basic transcription / with focus → targeted analysis)
  → PerceptionService.upsert (platform/telegram/media.rs:persist_analysis; key = source+parser+focus; async embedding-vector embedding best-effort)
```

- Same-file dedup: `domain/vo/resource.rs:resource_id_from_file_id` = UUIDv5(file_id), same resource keeps only the first attachment's perception (others recorded as `same_resource_as`, rendered with that attribute).
- `FileCache`: data_dir/files disk cache (key = `{platform}-{file_id}`, sanitize filename).

### MCP integration

- `agentcore/mcp.rs:McpManager::from_config(&AppConfig)`: loads from `[mcp.<name>]`; subprocess stdio (`kill_on_drop`), stderr → `tracing::debug!(target: "hai::mcp")`
- `list_all_tools()`: a single server failure only logs an error and does not abort; **any server connection failure at startup → overall startup failure** (asymmetric, `from_config` propagates with `?`)
- Tool results (`McpServerHandle::call_tool`): `structured_content` preferred, otherwise concatenate the Text blocks; `is_error` → ToolError; empty → `Value::Null`; non-JSON text → `Value::String`.

## Boundaries

- Tool contract (args schema) is generated by schemars from the Args structure, field table not restated here (grep yields it).
- No automatic tool retry (LLM-layer retry only for network-class errors); tool side effects executed sequentially (not in parallel).
- Wrap-up tool surface deliberately narrowed (topic/memory only) — background organization scenario.

## Pitfalls / common mistakes

- `skip`/`has_spoken` determination is a hardcoded string (`fn_name == "skip"` / send_message/send_voice, `agent/runtime/react.rs:run_react_loop`) — future new speaking-type tools or an MCP tool exactly named skip would falsely trigger ([INFERENCE]).
- `search_memory` nominally "by keyword" is actually semantic embedding-vector retrieval (`agent/tools/memory.rs:SearchMemory`) — when retrieval semantics are involved, first confirm it is vector recall.
- Multimodal video/audio request bodies use non-standard OpenAI types (`video_url`/`input_audio`), `extract_text` only accepts string content — compatibility is questionable when changing providers ([INFERENCE]).
- MCP tool description can be an empty string, passed through to the LLM as-is — tool-surface quality depends on each MCP server's metadata.
- Macro has no exec signature validation: a struct missing the corresponding exec yields an obscure compile error — when adding tools, first verify the macro's three forms.
- Legacy: `MessageCapability::Plain` removed.

## Evolution direction

- MCP startup fault-tolerance is asymmetric (startup failure → overall failure) — if per-server degraded startup is needed, change `from_config`'s fault-tolerance strategy.
